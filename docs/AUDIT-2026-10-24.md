# Audit — 2026-10-24

Full audit of `anyhop` (OpenAI-compatible LLM gateway, ~39 kLOC Rust + a
Sycamore/WASM dashboard). This round covered static analysis of every module,
the quality gates, the end-to-end suites, and a load/latency measurement. It is
the fourth recorded round (see `SECURITY-AUDIT.md`, `TEST-COVERAGE.md`,
`WIRE-VERIFICATION.md`, `FUZZING.md`, `test/chaos_findings.md`).

Everything below was reproduced, fixed, and re-verified on this tree. The
numbers in the verification matrix are from the final run.

---

## 1. How the audit was run

| Layer | What ran | Where |
| --- | --- | --- |
| Static review | Six independent read-only passes: proxy/pool core, provider adapters (Gemini, Anthropic, Codex, Antigravity, openai_compat), API/auth/config/storage, realtime+responses+media+ws, and the test harness/docs/feature matrix | parallel agents on this tree |
| Compile & unit | `cargo fmt --check`, `cargo clippy --all-targets`, `cargo test`, `cargo build --no-default-features` | build box (`homelab`), because local `cargo` refuses to compile on this workstation by policy |
| End-to-end | `test/run_all.sh` (mocks + gateway + hardening + CDP UI), `test/chaos_test.py` | locally, against the release binary built from this tree |
| Load/latency | `test/soak.py` (16 workers, 45 s, all mock providers) | locally |
| Live sanity | one real completion through a running instance (`antigravity/gemini-3-flash`) | local gateway on :8080 |

Two process findings about the tree itself:

* **The quality gate could not fail.** `test/audit.sh` decided "clean clippy" by
  counting lines that start with `warning`/`error` (a tool that cannot run prints
  neither), and "tests pass" by `grep -m1 "test result" | grep -oE "[0-9]+ passed"`
  — which reads `test result: FAILED. 575 passed; 3 failed` as **ok**, and only
  looked at the first test binary. Both gates now judge exit status.
* **The e2e gate tested whatever binary happened to be in `target/release`.** It
  never built one; a local `audit.sh` on this tree "verified" a binary two days
  older than HEAD. It now runs `cargo build --release` first.

## 3. Findings and fixes

Severity: **P0** exploitable/wrong-answer, **P1** breaks a documented feature or
takes a provider down, **P2** defect with a narrower trigger.

### 3.1 Security

| # | Sev | Finding | Fix |
| --- | --- | --- | --- |
| S1 | **P0** | **Allowlist bypass with a duplicate `model` key.** The byte scanner stops as soon as it has seen `model` and `stream`; `string_field_span` then reports the duplicate as ambiguous and the request was forwarded **verbatim**. So `{"model":"cheap",…,"model":"expensive"}` was authorized/routed as `cheap` and executed as `expensive` by any last-one-wins upstream (all of them). A client key allowlisted to one model could spend any model on that provider, and `disabled_models` was bypassed the same way. | The DOM decides when the span is not unique: the last value is what gets resolved, authorized, and pinned before the body is re-serialized (`proxy/chat/mod.rs`). Regression test in `run_all.sh` (routing integrity). |
| S2 | **P1** | **`max_concurrent` did not bound streams.** The client-key slot was stored in the *response extensions*; hyper drops those when it encodes the response head, i.e. before the body streams. A tenant with `max_concurrent = 1` could hold unlimited SSE streams — each of which also pins an upstream key slot. | The permit now rides inside the response body (`middleware.rs::hold_slot_until_body_ends`), the same pattern the provider guard already used. |
| S3 | **P1** | **A legal `Upgrade` header bypassed the slot entirely.** `require_api_key` matched the whole header value against `websocket`, while the realtime handler accepts a token list, so `Upgrade: websocket, foo` got a 101 with no client-key guard. | Split on `,` in the middleware, like the handler. |
| S4 | **P1** | **`/api/*` was unauthenticated when only `client_keys` were configured.** `require_admin_key` only looks at `api_key`/`admin_key`, so a config with tenant keys locked `/v1/*` while `GET /api/config` returned the raw TOML — every provider key, OAuth refresh token and client key. | `Config::validate` now refuses `[[client_keys]]` without `[server] api_key`/`admin_key`, with an actionable message. The startup warning was also wrong ("`/api/*` accept unauthenticated requests" while `/v1` did not). |
| S5 | **P2** | `GET /v1/models/{id}` ignored the client-key allowlist and the bare spelling of `disabled_models` — a restricted key could enumerate the catalogue (200 vs 404 one id at a time). *(A previous round's `TEST-COVERAGE.md` entry claims this was fixed; it was not in the code.)* | Same `model_allowed`/`combo_allowed` and both disabled spellings as `list_models`. |
| S6 | **P2** | `mask_key` revealed the whole secret for 9–11-character keys (`take(7)` + `skip(n-4)` overlap), and that mask is the default key **name**, which lands in a Prometheus label and in the event/request feeds. | Keys shorter than 16 chars are masked to `***`; longer ones show 7 + 4 with no overlap. |
| S7 | **P2** | The state file (OAuth tokens, runtime keys) was created with the process umask and chmod-ed afterwards; the chmod error was discarded. | Created with `0600` before redb opens it; a failing chmod is logged. |
| S8 | **P2** | The per-IP failed-auth budget was cleared by *any* successful client-key request, so one valid key plus `burst-1` guesses per round was never locked out (4-char keys are allowed). | Only the master key clears it; entries expire with the window. |
| S9 | **P2** | The histogram `MAX_SERIES` cap was exhaustible by unauthenticated 404s (`/api/<random-slug>/x` created one series each), after which every new series — including real routes' status codes — folded into `other` for the process lifetime. | Only known `/api` resources may grow an `{id}` series. |
| S10 | **P2** | Clearing the last credential was guarded by the *requested* `listen` (a restart-only field), so `{clear_api_key:true, listen:"127.0.0.1:…"}` on a live `0.0.0.0` gateway passed the check and left an unauthenticated admin API on a public socket. | The check uses the bound address, and changing `listen` in the same request as clearing a key is refused. |
| S11 | **P2** | `disabled_models` accepted any string: a 32 MiB entry was written into `anyhop.toml` (rewritten + fsynced in full on every toggle) and into the event feed. | Bound to 256 chars, no control characters. |
| S12 | **P2** | A model-scoped **403** marked the credential `DEAD` forever (it never self-recovers), and an OAuth 401 replayed the same cached access token until it expired. | 403 cools the key down unless the body names a model/region/billing policy; a 401 also invalidates the cached token so the next attempt refreshes. |

### 3.2 Protocol / correctness (wire level)

| # | Sev | Finding | Fix |
| --- | --- | --- | --- |
| W1 | **P1** | `responses` reported an upstream stream reset/timeout as **`response.completed`** (truncated text, `status: "completed"`, and the cut-off reply was stored for `previous_response_id`). The parser-error arm three lines above already called `fail()`. | Transport errors now emit `response.failed`. |
| W2 | **P1** | Realtime relayed the client's model id verbatim: only `?model=` was rewritten, so `session.update` still carried `session.model = "provider/model"` — and `session.model` wins, so the provider saw an unknown model (and `session.update` is atomic, so the rest of the message was dropped too). | Frames headed upstream have `model`/`session.model` rewritten to the upstream id. Test updated to assert the rewrite. |
| W3 | **P1** | Anthropic `base_url` ending in `/v1` produced `/v1/v1/messages` → 404, while `/v1/models` for the same provider worked (that path tolerates `/v1`). | `anthropic::messages_url` normalizes once. |
| W4 | **P1** | Anthropic `temperature`/`top_p` were forwarded unclamped; OpenAI's legal range is 0–2, Anthropic's is 0–1, so a valid OpenAI request got a hard 400. | Clamped; `top_p <= 0` is dropped. |
| W5 | **P1** | A thinking budget inflated `max_tokens`/`maxOutputTokens` past the model's own cap (`reasoning_effort: high` → 24 577 on an 8192-cap Claude, 25 600 on `gemini-2.0-flash`): a guaranteed 400 on exactly those models. | Clamped to a per-model output cap; the budget shrinks to fit. |
| W6 | **P2** | Gemini `finishReason` gaps (`OTHER`, `MALFORMED_FUNCTION_CALL`, `LANGUAGE`, `IMAGE_SAFETY`, …) mapped to `"stop"`, so a failed generation looked like a normal empty answer. | Mapped to `content_filter` (the existing `promptFeedback` branch covers the block case). |
| W7 | **P2** | `reasoning_effort: "none"` sent `thinkingBudget: 0` to `gemini-2.5-pro`, which rejects 0 (minimum 128) — a 400 on every Pro model. | `thinkingConfig` is omitted for models that cannot disable thinking. |
| W8 | **P2** | `reasoning_effort: "none"` mapped to `"minimal"` for Codex, i.e. reasoning **on**, and `minimal` is itself rejected by some models. | `none` omits `reasoning` (backend default). |
| W9 | **P2** | `response_format` was silently dropped for `anthropic` and `codex`: a `json_schema` request came back as prose with HTTP 200. | Codex maps it to `text.format`; Anthropic refuses it by name (no JSON mode exists there) instead of pretending. |
| W10 | **P2** | Anthropic prompt-cache tokens were not counted: `input_tokens` excludes `cache_read_input_tokens`/`cache_creation_input_tokens`, so a cached conversation reported a context far smaller than the real one (and the pool counters inherited it). | `prompt_tokens` sums the three buckets, `prompt_tokens_details.cached_tokens` is reported, streaming path included. |
| W11 | **P2** | Gemini embeddings doubled the `models/` prefix (`/models/models/…` → 404) and spliced the model into raw JSON without escaping (the chat path documents that exact bug). | Prefix stripped once, splice escaped. |
| W12 | **P2** | An embeddings response whose body failed to read was served as **200 with an empty body**. | 502. |
| W13 | **P2** | Codex forwarded `temperature`, which reasoning backends reject; `[tuning]` never reached the OAuth accounts' HTTP clients; Gemini model listing ignored `extra_headers`. | Temperature dropped for Codex (documented), tuning passed through, headers applied. |
| W14 | **P2** | `store: false` on `/v1/responses` was ignored (the conversation was written to the state file and replayable); `finish_reason: "length"` was reported as `completed`; streamed calls always reported `usage: 0/0` because nothing asked for a usage chunk. | `store: false` skips persistence; `length` emits `response.incomplete` + `incomplete_details`; `stream_options.include_usage` is set. |
| W15 | **P2** | WebSocket close frames were not UTF-8-validated, so an echo of an upstream close could emit a frame RFC 6455 §5.5.1 forbids. | Validated in `validate_close`. |

### 3.3 Resilience / failover

| # | Sev | Finding | Fix |
| --- | --- | --- | --- |
| R1 | **P1** | A saturated pool could stall `max_retries × capacity_wait_ms` (4 × 5 s = 20 s, × chain length for a combo) before the documented `429 Retry-After: 1`, with no upstream attempt made: `admit()` re-armed the full budget on every round. | One deadline per target; the remaining budget is passed in and a Busy round ends the target when it is used up. |
| R2 | **P2** | A capacity round overwrote (and masked) the real failure cause, so "busy → upstream 502" was answered as `429 rate_limit_exceeded`. | `keep_specific`, and the last real failure survives. |
| R3 | **P2** | Combo exhaustion replaced the last target's answer with a generic 503, dropping its `Retry-After` and the actual cause. | The last target's `failure_response` is reused. |
| R4 | **P2** | `Retry-After: 0` produced a zero-length cooldown (FillFirst re-picked the same key and ate the next 429 while other keys idled); an HTTP-date (`Retry-After: Wed, …`) was not parsed at all and fell back to a flat 60 s. Antigravity 429s ignored `Retry-After` entirely (flat 60 s per model). | `parse_retry_after` handles delta-seconds and IMF-fixdate, clamps to `1..=24 h`; the Antigravity branch prefers the exact reset, then the header, then 60 s. Shared with embeddings/media. |
| R5 | **P2** | A `200 application/json` answer to a `stream: true` request benched a healthy key and drove its exponential backoff to `max_cooldown` — client-triggerable provider outage. | A JSON-instead-of-SSE answer is a shape mismatch: 502 without a health penalty. |
| R6 | **P2** | Non-stream upstream bodies were buffered with **no size cap** and the key slot was released *before* the read, removing the pool's backpressure exactly where it was unbounded. | 64 MiB cap + the slot is held for the read. |
| R7 | **P2** | Media relays had no body deadline: a provider that sent headers and stalled held the client, both sockets and the key slot forever. | Per-chunk idle deadline (provider timeout). |
| R8 | **P2** | Per-model cooldowns grew without bound on a wildcard provider (`model` is client-chosen, every 429 inserts one, the health record is persisted each time). | Expired entries pruned on write, map capped at 256. |
| R9 | **P2** | `ArcSwap` guards were held across the whole upstream round-trip; `arc-swap` blocks `store()` until every reader on the old pointer drops, so a config save could wait one attempt timeout (120 s by default). | `load_full()` (owned `Arc`) on the long paths. |
| R10 | **P2** | The SSE parser refused a chunk larger than 1 MiB even when it contained many complete events, and could never relay a legitimate >1 MiB event (inline base64 media). | The cap now applies to the buffered partial event (with a 4× allocation guard), not to the read size. |
| R11 | — | **Throughput:** during a 200-request storm the pool reached its full 4-slot concurrency; the residual 429s were the queue budget expiring (5 s at ~28 rps), not fast-failing. The chaos check now asserts that contract (every 429 waited and carries `Retry-After`) instead of an unreachable ">90 % served". | `pool::pick_ready` keeps admission capacity-aware and explicitly tested. |

### 3.4 Performance

Measured, not assumed (`test/soak.py`, release build, all mock providers):

```
273 945 requests in 45.1 s -> 6 078 req/s, 0 errors
latency p50 1.9 ms / p95 3.6 ms / p99 4.6 ms
RSS 11 MB -> 17 MB (delta +6 MB over the run), fds 12 -> 12 at rest
```

Hot paths were left zero-copy where they were already (pass-through body, model
splice). The fixes that touch the request path add no allocation in the common
case: the duplicate-`model` DOM path only runs when the body really is
ambiguous, and the capacity deadline replaced a per-round timer.

## 4. Not fixed / known gaps (with reasons)

1. **Redis token-bucket Lua is still never executed.** `distributed/limiter.rs`
   ships a Lua script; the gateway's Rust fallback and `test/mock_redis.py` are
   two independent re-implementations, so the suite proves they agree — not that
   the Lua is correct. No `redis-server` exists on the audit host; a real-Redis
   job (docker or an embedded Lua interpreter) is the fix.
2. **`/v1/audio/transcriptions` and `/v1/audio/translations` have no e2e test.**
   The mock supports both; only `images`/`speech` are exercised.
3. **`/v1/responses` streaming events** are covered by unit tests of the mapper,
   not by an HTTP-level client asserting the event sequence.
4. **Soak is not wired into a gate** and can pass vacuously (see T4).
5. **Bare-CR (`\r`) SSE line terminators** are not treated as event boundaries
   (only `\n` / `\r\n`). No real provider does this; buffering it costs one
   oversized event at worst.
6. **Anthropic JSON mode** is refused rather than emulated through a forced
   tool call; that is a missing feature, not a bug, and it is now explicit.
7. **`store`** is honoured on the request but not echoed in the response object
   (the rest of the Responses object is unchanged).
8. **`antigravity::loadCodeAssist`** still targets the production endpoint
   regardless of a configured `base_url` (a region/alternate-host setup would
   discover the project on prod).
9. **`ui/src` changed; `ui/dist` here is stale** — rebuild it with trunk before
   shipping an embedded dashboard (CI's `ui` job and the Dockerfile both do).

## 5. Behaviour changes worth knowing

* `[[client_keys]]` without `[server] api_key`/`admin_key` is now a **startup
  error** (it used to leave `/api/*` open).
* Codex no longer forwards `temperature`; Anthropic refuses `response_format`
  with a 400 instead of silently dropping it.
* A `403` no longer kills a credential unless the body looks like a credential
  error; it cools the key down instead.
* A streaming request that receives JSON gets `502` (explicit message) instead of
  a benched key.
* `Retry-After` is honoured in both spellings and never zero.

The running instance on `127.0.0.1:8080` keeps the **old** binary until it is
restarted (`systemctl restart anyhop`, or `./scripts/run.sh`); `target/release/anyhop`
is already replaced with the audited build.
