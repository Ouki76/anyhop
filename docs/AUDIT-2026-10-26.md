# Audit — 2026-10-26

Full audit of `anyhop` (OpenAI-compatible LLM gateway, ~44 kLOC Rust + a
Sycamore/WASM dashboard). Five independent read-only passes covered security,
performance, correctness, standards conformance and the test/CI surface; the
findings below were each reproduced against this tree before being fixed.

This document is the record of **what changed in this round** and why. It is the
fifth recorded audit (see `SECURITY-AUDIT.md`, `TEST-COVERAGE.md`,
`WIRE-VERIFICATION.md`, `FUZZING.md`, `AUDIT-2026-10-24.md`).

## 3. Findings fixed in this round

Severity: **P0** exploitable/wrong-answer, **P1** breaks a documented feature or
leaks a credential, **P2** defect with a narrower trigger, **P3** hygiene.

### 3.1 Security

| # | Sev | Finding | Fix |
| --- | --- | --- | --- |
| S1 | **P0** | **The gateway key *was* the admin credential.** `/api/*` accepted `rt.admin_key.or(rt.api_key)`, and `api_key` is pasted into every client (Open WebUI, Cursor, Chatbox, a shell alias). One leaked client credential therefore read every provider key and OAuth refresh token (`GET /api/config`), revealed every tenant secret (`POST /api/client-keys/reveal`) and rewrote the config (`PUT /api/config`) — the per-tenant `[[client_keys]]` model erased. | `require_admin_key` checks `admin_key` **only**; the two `.or(api_key)` fallbacks in `RtConfig` are gone. `Config::validate` refuses client keys without an `admin_key`, so the dashboard cannot be silently locked out. Startup now warns explicitly when `api_key` is set but `admin_key` is not. Regression tests in `middleware::admin_key_is_not_the_gateway_key`. |
| S2 | **P1** | **Ambient proxy variables intercepted every provider credential.** `reqwest` 0.12 enables `system-proxy` by default, so `HTTPS_PROXY`/`ALL_PROXY`/`HTTP_PROXY` were honoured even with no proxy configured — whoever controls the process environment (an `EnvironmentFile=`, a compose `env_file`, a parent process) received `Authorization: Bearer <provider key>`, `x-api-key` and `x-goog-api-key` for every upstream call, plus plaintext replies. | `.no_proxy()` on the upstream client builder: a proxy is opt-in and explicit (`[server] proxy` or a per-provider `proxy`). Proven behaviourally by `providers::tests::ambient_proxy_env_does_not_intercept_upstream_calls`, which points the variable at a recording listener and requires that it sees nothing. |

### 3.2 Protocol / standards conformance

| # | Sev | Finding | Fix |
| --- | --- | --- | --- |
| W1 | **P1** | **`error.code` was an integer.** The OpenAI `Error` schema types `code` as `string \| null`; typed SDKs (`openai-python`'s `APIError.code: Optional[str]`) break on a number, and clients branch on tokens like `insufficient_quota`. `error.param` was missing entirely although the schema marks it required. | One envelope (`proxy::error_response`, used by 90 call sites) now emits a **string** code derived from the error type and always-present `"param": null`. `middleware::json_errors` (axum's own rejections) uses the same shape via `proxy::error_code_for`, so the two paths cannot drift. Tests updated to assert the string form and `param == null`. |
| W2 | **P1** | **Broken `Access-Control-Allow-Headers`.** The literal carried a run of **22 spaces** where a `, ` belonged (a lost line continuation) and went out verbatim. A browser splits the value into tokens, so `openai-organization` and `openai-beta` never matched and a preflight that sent either failed — for exactly the header set an OpenAI-compatible client sends. | Rewritten as a `concat!` of properly separated tokens, extended with the `x-request-id`/`x-stainless-*` headers real OpenAI SDKs send. |
| W3 | **P2** | **Secrets were cacheable.** `/api/*` returns plaintext provider keys, OAuth refresh tokens and revealed client keys with no caching directive; a shared cache behind a TLS-terminating proxy, or a browser back/forward store, keeps such a body. | `Cache-Control: no-store` + `Pragma: no-cache` on every `/api/*` response, set once in the outermost hardening layer so a new handler cannot forget it. `/v1/*` is untouched (caching a model list is the point). Test: `api_responses_are_never_stored_by_a_cache`. |
| W4 | **P2** | **`Vary: Origin` was only sent for a matched origin.** RFC 9110 §12.5.5 requires a cache to key on every field that changed the response; a request *without* `Origin` yields different headers, so an intermediary could store the no-`Origin` variant and replay it to a cross-origin client — which then sees no CORS headers at all. | Sent on every response while CORS is configured. Pinned by `an_unlisted_origin_gets_no_cors_headers`. |

### 3.3 Correctness and resilience

Each was a real wrong-answer or resource bug, reproduced before being fixed.

| # | Sev | Finding | Fix |
| --- | --- | --- | --- |
| C1 | **P1** | **A truncated Anthropic stream looked complete.** `message_delta` that carries only `usage` (legal, and common) emitted no chunk with a `finish_reason`, and a stream that then closed — upstream reset, idle deadline — left the client with text, a usage chunk and `[DONE]`, i.e. an interrupted answer indistinguishable from a finished one. The module's own `fail()` doc promises the opposite. | `SseState::finish_sent` tracks whether a reason was emitted; `finish_if_missing()` runs on `message_stop`, on a clean EOF and before the terminal frames. A healthy stream still reports its reason exactly once. Test: `a_stream_without_a_stop_reason_still_reports_a_finish_reason` (both branches). |
| C2 | **P1** | **Prompt-cache tokens were counted two ways.** The non-streaming Anthropic path read `usage.input_tokens` raw while the streaming path and the translated body used `prompt_usage` (which adds `cache_read_*` and `cache_creation_*`). The same conversation reported 12 tokens in the pool counters and 30 012 in the response, so per-key usage and the dashboard were wrong for exactly the prompts caching exists to save. | `anthropic::prompt_usage` is `pub(crate)` and the non-stream call site uses it. Test: `cached_prompt_tokens_are_counted_the_same_on_every_path` pins all three paths to one number. |
| C3 | **P1** | **A healthy key could be benched by one client.** `is_json_like("")` was false, so a compat upstream that answers `200 application/json` **without** a `Content-Type` (legal — the header is optional) to a `stream: true` request was classified as a provider fault: 5xx backoff for the key and a 502 for the client. `accept_2xx` already treats an absent type as fine on the non-streaming branch, so the two predicates disagreed. | `is_json_like` normalises through `normalize_content_type` (so `; charset=` and case cannot split them) and treats an empty type as JSON-ish. Test: `an_absent_content_type_is_a_shape_mismatch_not_a_provider_fault` asserts the two predicates **agree** on every case. |
| C4 | **P1** | **FIM was broken on Gemini/Antigravity.** The wrapped path synthesises `stop: ["\n\n\n"]` for chat models; `gemini::translate_request` forwarded it into `generationConfig.stopSequences`, whose strings reject control characters — a deterministic `400 INVALID_ARGUMENT` on every autocomplete. | Both translators drop stop sequences containing control characters (or empty) instead of forwarding a request that is guaranteed to fail. Test: `stop_sequences_with_control_characters_are_dropped_not_forwarded` (also asserts the field is omitted rather than sent empty). |
| C5 | **P1** | **Redis reconnect replay double-charged a token.** The pool transparently replayed a command after a transport failure on a reused socket, justified by "every command sent through this pool is idempotent" — false for the token-bucket `EVAL`, which is a read-modify-write. After any Redis restart or failover the shared budget drained at up to 2× `rpm`, so a client running at exactly `rpm` saw spurious 429s. | `call_with(args, replay_on_reconnect)`; `eval` passes `false`, so the caller sees the transport error and the limiter's own policy (`fail_open`, or a 429 with `Retry-After`) decides. Read-only commands still recover transparently. Test: `a_state_mutating_command_is_not_replayed_on_a_dead_socket`. |
| C6 | **P2** | **`least_used` degenerated into `fill_first` under burst.** It ranked on `requests`, which only increments *after* a round trip, so every request in a concurrent burst read the same counts and picked the same key — pinning one credential while the rest sat idle, exactly when the strategy was needed. | Ranks on `(in_flight, requests)`: live load first (what a burst competes over), lifetime count as the tie-break so sustained traffic still spreads. Test: `least_used_spreads_a_concurrent_burst`. |
| C7 | **P2** | **Sticky eviction was a cliff.** `bind` called `map.clear()` at `sticky_max_entries`, dropping *every* live conversation's key binding at once — undoing the prompt-cache pinning for everyone — and one request paid for thousands of frees. | Expired entries go first; only then the oldest quarter. Test: `eviction_at_the_cap_keeps_the_newest_bindings` + `expired_bindings_are_evicted_before_live_ones`. |
| C8 | **P1** | **`base_url` scheme was unvalidated on the TOML path.** The dashboard edit path checked `http(s)://`; `Config::validate` only checked "not empty". The runtime concatenates URLs (`format!("{base}/chat/completions")`) with the provider key attached, so a hand-written `file://`, `gopher://` or `ws://` reached `reqwest` verbatim — reachable through `PUT /api/config`. | One `config::is_http_url`, used by both paths. Test: `a_base_url_that_is_not_http_is_rejected` (and an empty value stays legal for kinds with a default endpoint). |

### 3.4 Performance

Measured, not assumed: `cargo bench --bench hot_paths` for the micro level,
`test/soak.py` for the end-to-end picture.

| # | Sev | Finding | Fix |
| --- | --- | --- | --- |
| P1 | MEDIUM | **Five allocations per request in the metrics layer.** `record_metrics` copied the path *and* the method to `String`, then allocated the route label, then allocated a two-`String` map key — on 100% of requests, including the 401s an unauthenticated caller can generate at will. | The route label is the one allocation that is genuinely needed (it is the series identity). The method is normalised to a `&'static str` from the closed set `record` already built, so the map key costs nothing extra. |
| P2 | MEDIUM | **A full `RtConfig` clone per request.** `AppState::rt()` did `RwLock::read().clone()` of `api_key`, `admin_key` and a four-`String` `RateLimitConfig` on every `/v1/*` and `/api/*` request — ~25k avoidable allocations/s at 5k rps — although `Tuning` had already been moved to `ArcSwap` for exactly this reason. | `cfg` is an `ArcSwap<RtConfig>`; `rt()` returns `Arc<RtConfig>`, so a reader clones a pointer. One production write site (config install) became `store()`. |

The remaining allocation in the request path is the route label, which is the
histogram series identity and cannot be avoided without changing what `/metrics`
reports.

### 3.5 Correctness found by a user report: reasoning was invisible

| # | Sev | Finding | Fix |
| --- | --- | --- | --- |
| C9 | **P1** | **Gemini's thoughts were never returned unless the client asked.** `includeThoughts` is what makes the provider emit thinking parts at all, and the translator only set it inside the `reasoning_effort` branch. A client that did not send that field — DSH, most OpenAI-compatible UIs — got an empty "Think" panel even though the model was reasoning. Reported from a live DSH session against `antigravity/gemini-3.8-flash`. | For a model that reasons (`gemini-2.5`, `gemini-3`, `-pro`) an unstated effort now sends `thinkingConfig: {includeThoughts: true}` with **no budget**, so the provider keeps its own dynamic policy and only visibility changes. An explicit effort still wins (`none` hides them, `high` also raises the budget), and a model without a thinking mode (`1.5`, `2.0`) is never asked. Tests: `a_thinking_model_returns_its_thoughts_without_being_asked`, `a_non_thinking_model_is_not_asked_for_thoughts`, `an_explicit_effort_overrides_the_default_thought_visibility`, `the_antigravity_envelope_keeps_the_thought_flag`. |

### 3.5b Round 4: scenario-based hunt (concurrency, error paths, protocol)

The earlier passes went module by module. This round went by *scenario* — races,
failure paths, and protocol edge cases — with three focused read-only agents.

**Concurrency** (no deadlock and no memory unsafety found; two data-loss bugs did):

| # | Sev | Finding | Fix |
| --- | --- | --- | --- |
| R1 | **HIGH** | **Two dashboard tabs could lose each other's model edits.** `model_enable`/`model_disable`/`model_toggle`/`models_limits_set` read the current list *before* taking `config_lock`, so both wrote the list they had read and the first edit vanished from the TOML **and** from memory. `persist.rs` documents this exact race as fixed for client keys; these two lists never got the treatment. | `persist::with_locked_list` takes the snapshot **inside** the lock; every disabled-model and model-limit handler now goes through it. The racy `current_disabled`/`save_disabled` helpers are deleted so the pattern cannot come back. Tests run ten and eight *concurrent* requests and assert every edit survives in memory and on disk. |
| R2 | **MEDIUM** | **A limits change leaked in-flight permits.** `ClientKeyRuntime::rebind` kept the live `in_flight` counter only when `rpm`/`burst` were unchanged; otherwise `new_with` started a fresh `AtomicU32(0)` while the guards of in-flight requests decremented the *old* one. Each such reload leaked one permit per in-flight request, and a busy tenant drifted permanently over its cap. | The fallback branch now shares all three live counters (`in_flight`, `limited`, `saturated`). Test asserts the counter is the *same allocation*, not a copy. |

**Error paths and resources:**

| # | Sev | Finding | Fix |
| --- | --- | --- | --- |
| R3 | **HIGH** | **A crash mid-rewrite could empty `anyhop.toml`.** The in-place fallback (single-file bind mounts, the documented container case) opened with `truncate(true)` *before* writing, so a SIGKILL or ENOSPC in that window left a zero-byte config — and the error path deleted the only good copy. | The new bytes are written over the existing content and the length is fixed afterwards, so the worst case is a stale tail that the next write repairs. `truncate(false)` is now explicit with the reason. |
| R4 | **HIGH** | **A refused key delete wiped the persisted runtime-key list.** `delete_extra_key` + an unconditional `set_extra_keys(provider, [])` ran *before* `write_validated`; on the error path the restore was an async send to the writer task, so a process exiting before its next flush left the state file saying "no runtime keys" while the TOML still listed them — and those credentials disappeared on restart. | The storage mutation now happens only after the config write succeeds. |
| R5b | **LOW** | **A broken config made OAuth report a timeout instead of the error.** `auth_start` read `public_url` with `Config::load(...).ok()`, so a parse error silently meant "loopback only" — the operator waited for a callback their browser could never reach and got an authorization timeout minutes later. | The load error is returned to the dashboard. |
| R5 | **MEDIUM** | **`Retry-After: 1` on a busy gateway was a lie.** `busy_response` hardcoded `1` even with `capacity_wait_ms = 30 000`, and `admit` had already spent that budget: a client obeying the header walked into another 30 s poll. | The remaining capacity budget rides on `TargetFailure::Capacity` and is advertised. |

**Protocol and translation:**

| # | Sev | Finding | Fix |
| --- | --- | --- | --- |
| R6 | **HIGH** | **The Gemini thinking budget was never clamped to `maxOutputTokens`.** The clamp applied to the ceiling only, so `reasoning_effort: "high"` sent `thinkingBudget: 24576` next to an 8192 ceiling — impossible on 1.5/2.0 (400) and, on 2.5/3, budget == ceiling so thinking could consume the whole answer and the client got `finish_reason: "length"` with empty content. `anthropic.rs` already clamped; Gemini did not. | The budget is clamped to `ceiling - 1`. Test asserts `budget < ceiling` for every generation and that a generous ceiling keeps the full requested effort. |
| R7 | **HIGH** | **Codex silently dropped attachments.** `_ => {}` in `user_content` discarded `input_audio`/`file` parts, so an audio or document request returned HTTP 200 with an answer written as if the attachment had never existed — and an audio-only message went upstream with `"content": []`. | Untranslatable parts are a local 400 naming the type (the rule the Gemini translator already states in its own docs), and an empty part list is refused. |
| R8 | **MEDIUM** | **`{"type":"required"}` was silently ignored.** Both Anthropic and Codex handled only the `{"type":"function",…}` object form, so OpenAI's usual object spelling fell through and the backend defaulted to optional tools. | The object arm now maps mode types (`none`/`required`/`auto`) as well as a named function. |
| R9 | **MEDIUM** | **Gemini tool-call ids collided across turns.** `call_{now_secs()}_{n}` embedded a one-second clock, so two turns a second apart produced the identical id and a multi-step agent loop correlated every result to one call — the exact bug the surrounding comment claimed was fixed. | Ids come from a process-wide counter and never touch the clock. |
| R10 | **MEDIUM** | **Hosted tools were dropped instead of refused on `/v1/chat/completions`.** `README.md` promises a 400 for `web_search`/`file_search`/`code_interpreter` and `/v1/responses` produces one; the translating providers filtered the entry out and answered 200. | One shared `ensure_no_hosted_tools`, applied by all three translators, naming the tool. |
| R11 | **MEDIUM** | **Invalid generation parameters reached the provider.** `max_tokens: 0`/`-5`, a non-numeric budget, `temperature: 999` (Gemini's range is 0–2), `top_p: 0` (an empty nucleus) and `n: 3` (one choice comes back) were forwarded verbatim or silently truncated. | Rejected locally with the field named — `n > 1` is refused by all three translators, budgets must be ≥ 1, sampling is clamped, `topP: 0` is dropped. |
| R12 | **MEDIUM** | **An empty conversation hit the provider.** Anthropic sent `messages: []` (a guaranteed upstream 400) where Gemini already refused the same body locally. | Both now answer "no user or assistant messages". |
| R13 | **MEDIUM** | **A stream ending without `[DONE]` was passed through verbatim.** A provider or proxy that closes the body without the terminator left OpenAI clients waiting or treating a complete answer as truncated. | The pass-through relay synthesises `[DONE]` when the upstream never sent one, and never doubles it when it did. |

### 3.6b Round 5: conformance against the published specs

This round checked the translators against the **machine-readable** specs rather
than from memory (they were geo-blocked as prose docs, so the audits used
`openai/openai-openapi` 2.3.0, `@anthropic-ai/sdk` typings, the `googleapis/
python-genai` types and Mistral's OpenAPI), plus LiteLLM's mapping tables as a
cross-check where the spec is silent.

| # | Sev | Finding | Fix |
| --- | --- | --- | --- |
| S1 | **HIGH** | **Anthropic thinking budget could be emitted below the 1024 minimum.** The clamp was `.max(1)`, so a small `max_tokens` produced a budget of 1–1023 — a guaranteed 400. The spec has two rules: `budget >= 1024` *and* `budget < max_tokens`. | Clamped to `1024..=max_tokens-1`; when the ceiling cannot fit a legal budget, `thinking` is dropped rather than sent illegal (with a debug line saying why). |
| S2 | **HIGH** | **An image inside a tool result was silently dropped.** `tool_result.content` accepts a string *or* an array of content blocks; the translator flattened it to text, so a screenshot tool's picture vanished with no error — against the module's own stated rule. | Tool results now pass text and base64 images through as blocks, and refuse a part type they cannot express. `split_data_url` is shared with the message-parts path so the two cannot disagree. |
| S3 | **HIGH** | **An image on a Gemini assistant turn was silently dropped.** Same class: `content_text` kept only text. | The assistant turn uses `content_parts` (text + `inline_data`), which also refuses untranslatable parts. |
| S4 | **HIGH** | **`/v1/fim/completions` ignored `stream`.** DeepSeek, Mistral and OpenAI `/completions` all document SSE; the gateway forced `stream: false` in both paths and answered a single JSON object — a silent divergence. | The native path honours the flag and relays the provider's own SSE; the wrapped path asks for a chat stream and translates each delta into a `text_completion` chunk, then `[DONE]`. Live-verified. |
| S5 | **HIGH** | **Responses `output_index` collided.** The message item was announced with a hard-coded `0` and `output_index` was recomputed at close time, so probe-measured: `added(0, function_call)`, `added(0, message)`, `done(0|1, function_call)`. Any client keying items by `output_index` mixed them up. | The index is fixed when an item is announced and stored per item; the message takes one past every announced tool item; text events read the stored value. |
| S6 | **MEDIUM** | **`stream_options.include_usage` was ignored.** Anthropic emitted the usage chunk unconditionally; Gemini attached `usage` to a *content* chunk, a shape the schema does not permit. | Threaded through to both translators: one `choices: []` chunk before `[DONE]`, only when asked. Gemini's usage is remembered and emitted at the end; `push_usage` runs before the `take()` that the pool accounting does. Live-verified on both. |
| S7 | **MEDIUM** | **Gemini tool results used `role: "user"` and never sent `functionResponse.id`.** The SDK builds the turn as `role: "tool"`, and `id` is what disambiguates two parallel calls to the same function. | `role: "tool"` plus `functionResponse.id` taken from `tool_call_id`. Verified: two parallel `get_weather` calls now correlate exactly. |
| S8 | **MEDIUM** | **Anthropic `compaction` mapped to `stop`.** A turn cut short to fit the context window was reported as a complete answer. LiteLLM maps it to `length` for the same reason. | Mapped to `length`; every documented `stop_reason` is now pinned by a test. |
| S9 | **MEDIUM** | **Invalid generation parameters reached the provider** (from the same round): `max_tokens` 0 or negative, a non-numeric budget, `temperature: 999` on Gemini (range 0–2), `topP: 0` (empty nucleus), `n: 3` (one choice comes back), FIM `max_tokens` with no ceiling. | Rejected locally naming the field; `n > 1` refused by all three translators and by FIM; sampling clamped; FIM capped at the documented 4096. |
| S10 | **LOW** | **`user` was never forwarded**, so a client could not correlate with the provider-side usage log even though Anthropic documents `metadata.user_id`. | Forwarded; the fields with no equivalent (`seed`, penalties, `logit_bias`, `logprobs`) now log once at debug instead of vanishing. |

### 3.6d Round 5b: the three judgement calls, resolved

The conformance audit left three items as "maintainer's intent". They are now
decided and implemented:

| # | Item | Decision |
| --- | --- | --- |
| T1 | `GET /v1/models` omitted the schema-required `created` | **Stamped on first sight**, not `now()` per request: `AppState::model_first_seen` remembers when this process first served an id, so the value is stable across calls (a moving `created` would make any client diffing the catalogue see permanent churn). A restart re-stamps, which is the honest answer for a process-local catalogue. Test asserts stability across a >1 s gap. |
| T2 | `parallel_tool_calls: false` was silently ignored | **Forwarded where the provider has the control, refused where it does not.** Anthropic has `tool_choice.disable_parallel_tool_use`, so the flag rides on the choice (and creates `{"type":"auto","disable_parallel_tool_use":true}` when the client sent no `tool_choice`). Gemini has no equivalent — its `toolConfig` only offers AUTO/ANY/NONE and an allow-list — so the request is refused by name rather than answered with several calls the client did not ask for. |
| T3 | `completion_tokens_details.reasoning_tokens` was never emitted | **Read from the provider that reports it.** Anthropic puts the thinking share at `usage.output_tokens_details.thinking_tokens`; both the non-streaming body and the streaming usage chunk now carry it (0 when absent, so a client indexing the field never sees `undefined`). Gemini already surfaced `thoughtsTokenCount`. |

### 3.6c What the same audit confirmed is *correct* (do not "fix")

* `thoughtSignature` as a **sibling** of `functionCall` — the spec puts it on `Part`, not on `FunctionCall`.
* `parameters` in `function_declarations` on v1beta, and `responseJsonSchema` (public API) vs `responseSchema` (v1internal) split between the two translators — correct, and better than the prose docs imply.
* `system_fingerprint` absent everywhere: optional **and deprecated** in the current OpenAI schema.
* Gemini `finishReason` coverage is complete across all 16 documented values, and `STOP`-with-tool-calls is upgraded to `tool_calls`.
* A stream with no `stop_reason` gets a synthesised `finish_reason`; unknown upstream event types cannot break either stream.
* Pass-through relays faithfully, synthesises a missing `[DONE]`, and injects an error frame on a mid-body failure.

### 3.6e Round 6: a live provider error the audits predicted but the tests missed

The first request after the previous round failed in production with:

```
400 INVALID_ARGUMENT: Function call is missing a thought_signature in functionCall
parts. This is required for tools to work correctly … function call `memory_search`,

```

| # | Sev | Finding | Fix |

### 3.6f Round 7: making the signature survive any client

The placeholder from §3.6e stops the 400, but Google documents that it "will

| # | Sev | Finding | Fix |

| L2 | **P1** | **The real signature never came back.** OpenAI's tool-call schema has no field for it, so a standard client (DSH, the official SDKs, anything not written for Gemini) echoes only the tool-call **id**. ### 3.6i Round 10: the header deadline, and what three failed attempts taught

The last open gap: between `accept` and the first request byte there was **no
deadline at all**. A plain-HTTP client that connects and sends nothing held a file
descriptor forever; enough of them and the accept loop starves. (TLS had
`HANDSHAKE_TIMEOUT`, so only the plain listener was exposed.)

| # | Sev | Finding | Fix |
| --- | --- | --- | --- |
| L7 | **P1** | **Slowloris on the plain-HTTP listener.** `client_body_timeout_secs` bounds the body, the idle timeout bounds a parked keep-alive connection, and TLS bounds the handshake — but the window between accept and the header block was unbounded. | `[tuning] client_header_timeout_secs` (default 10 s) plus a `HeaderDeadline` listener that reads the header block under that deadline and hands hyper a stream that begins exactly there. Measured with a 3 s setting: silent, one-byte, half-request-line and headers-without-terminator clients are all dropped at **3.0 s**, while a normal request still returns 200. |

**Three implementations were wrong before this one, and each was caught by
measurement, not by review.** Worth recording because the pattern will recur:

1. **Timer inside `poll_read`.** Created a fresh `sleep` on each poll, so it
   restarted on every wake-up and could never fire.
2. **Absolute deadline inside `poll_read`.** Logically correct, but hyper does not
   poll a read until it believes the connection is ready — for a silent client
   `poll_read` is *never called*, so the guard never ran. Confirmed by a total
   absence of its log line across a 20 s stall.
3. **Deadline covering the first byte.** Passed the "silent client" test and
   failed the real attack: one byte of `G` satisfied it and the socket then hung
   for 25 s+.

The working design reads the **whole header block** (`\r\n\r\n`), not the first
byte, and enforces it in `accept` where nothing else competes for the socket. Three
tests pin it: byte-exact replay, stalled client, silent client.

### 3.6k Round 11b: the opt-out that did not exist

The finite client-key default exposed a latent defect in the merge rule:

| # | Sev | Finding | Fix |
| --- | --- | --- | --- |
| S5 | **HIGH** | **`max_concurrent = 0` on a client key did not mean "unlimited".** The runtime stored the override as `u32`, so `None` ("inherit") and `Some(0)` ("opt out") both collapsed to `0`, and the merge read `0` as "inherit the server default". The documented opt-out was therefore impossible — silently. Invisible while the server default was also `0`; the moment the default became 64, a scenario that explicitly asked for unlimited started getting fast 429s at exactly 64 in flight. | The runtime now keeps `Option<u32>` and the merge is explicitly three-state: `Some(n)` = this key's cap, `Some(0)` = unlimited for this key, `None` = inherit the server default. The startup warning's predicate follows the same resolution. `zero_is_an_override_not_an_absence` pins all three states, and `the_default_is_finite_and_zero_still_parses` proves `0` survives TOML parsing as `Some(0)`. |

**How it surfaced:** the chaos suite failed at `64/200 served, 136 x 429, median wait
0.00s` — a round number, which is what gave it away: the refusal came from the
client-key layer, not from the upstream pool the scenario is meant to exercise. Two
test fixtures also asked for `max_concurrent = 0` explicitly; they now do so
deliberately and say why.

## 4. What was verified sound

Worth not breaking. Each was checked deliberately.

* **`token_eq`** — length-checked, byte-wise XOR accumulator, no early exit, multibyte-safe. Every credential comparison goes through it.
* **OAuth** — 32 `getrandom` bytes, single-use, expiry-bounded, empty/clock-shaped states rejected, delivery rate-limited through the shared failure gate, HTML fully escaped under `default-src 'none'`.
* **Auth middleware** — failures counted *after* comparison; lockout is a response to a bad credential, never a pre-filter; per-IP map hard-capped with sweep/evict; `Retry-After` is the remaining window, rounded up.
* **Client-key concurrency** — the guard rides the response *body* stream, so SSE cannot bypass `max_concurrent`; the upgrade handoff is keyed on `/v1/realtime`, not on the `Upgrade` header.
* **`src/ws.rs`** — the most spec-conformant file in the tree: per-direction masking enforced, length checked from the prefix *before* allocating, 64-bit MSB rejected, control-frame FIN/≤125 rules, close-code and UTF-8 validation, fragmentation caps, buffer shrink, cancel-safe reader; hand-rolled SHA-1 pinned to the RFC vectors. **Zero RFC 6455 deviations found.**
* **`src/sse.rs`** — CRLF/LF/mixed framing, multi-line `data:` joined per spec, comments/`event:` ignored, mid-event chunk splits; byte-oriented so a split multi-byte character cannot panic or corrupt; sticky 1 MiB cap with bounded buffering.
* **`src/distributed/redis.rs`** — `MAX_LINE`/`MAX_BULK`/`MAX_ARRAY`/`MAX_DEPTH` plus a byte `Budget` charged before allocation; `Resp::summary()` avoids `Debug` of wire data; the password never reaches a log line or a bucket name (the bucket name is a digest).
* **Translators** — Anthropic block index capped, usage sums saturate, prompt-cache buckets counted, thinking budget clamped so `max_tokens > budget`, `response_format` refused by name; Gemini stop-sequence clipping, `thinkingBudget: 0` only where legal, tool ids from a counter not the clock.
* **Responses API** — every input/output budget, ownership check on `previous_response_id` returning the same 400 as "unknown" (no oracle), `store:false`, `finish_reason:"length"` → `response.incomplete`, mid-stream transport error → `response.failed`.
* **Storage** — bounded pending batch with requeue, deterministic newest-first eviction, per-record and recent-window caps, `0600` before redb opens, one write transaction per flush.
* **Rate limiters** — `saturating_duration_since`, idle credit capped at capacity, `Retry-After` rounded up in both backends, and the Lua script clamps a forward clock jump to one refill.
* **`src/tls.rs`** — ring provider, strict manual PEM parsing with block matching, handshakes off the accept path behind `MAX_HANDSHAKES` + a 10 s timeout.
* **`src/dashboard.rs`** — exact-path embedded lookup with explicit traversal rejection; CSP hash-pins every inline script body (raw, not trimmed) and applies on all three index URLs; `default-src 'none'`, `frame-ancestors 'none'`, `base-uri 'none'`, `form-action 'none'`, `'wasm-unsafe-eval'` (never `'unsafe-eval'`).
* **`src/scan.rs`** — duplicate/escaped `model` keys force a real DOM parse, so authorization and the upstream cannot disagree (the prior allowlist bypass).
* **Deployment** — Dockerfile runs uid 10001, `read_only`, `no-new-privileges`, `cap_drop: ALL`; the systemd unit is sandboxed with `UMask=0077`.
* **No `unwrap`/`expect` in production paths** (crate-level `deny`), and no `std::sync` guard crosses an `.await` anywhere in the tree.
